# 05 · 开发计划

> 编写日期：2026-11-02 ｜ 依据：[04 单屏布局设计 v6](04-单屏布局设计.md)（已定稿）
> 目标：把 v6 那一屏"从图纸变成能长期挂在桌上的设备"。

---

## 0. 一句话

在 AI-Thinker ESP32-CAM 上（拔掉摄像头）用 Arduino 框架驱动 SSD1315 OLED，实现：**时间 / 日期+星期+农历 / 天气（图标+温度+H/L+降雨概率+风）/ WiFi 状态 / 最后更新时间**，配网页可改 WiFi、可 OTA；地点固定苏州。

## 1. 交付范围（验收即按这张表逐条过）

| ID | 需求 | 验收标准 |
|---|---|---|
| R1 | 时间 `HH:MM:SS` 24h | NTP 同步后与手机对比误差 < 1s；秒每秒跳变，画面不抖 |
| R2 | 日期 + 星期 + 农历 | `11-02 周一 九月廿四`；农历与黄历 App 一致 |
| R3 | NTP 每 12h 校准 | 改板载时钟偏移后 12h 内被拉回 < 1s（可用日志验证） |
| R4 | WiFi 状态 | 在线 `WiFi OK`，断网 10s 内变 `WiFi NO`，恢复后自动变回 |
| R5 | 天气 | 图标 + 温度 + `H 30` `L 20` + 降雨概率 + 风向风级；与手机天气偏差 ≤ 1℃（同源数据） |
| R6 | 断网降级 | 断网后保留最后一次数据，右下更新时间停住，时间照走 |
| R7 | 配网页 | AP 模式 `192.168.4.1` 可填 WiFi；页面可触发"刷新天气"与"升级固件" |
| R8 | OTA | 网页上传固件成功重启，版本号变化；ArduinoOTA 也能推 |
| R9 | 显示质量 | 无花屏、无残影、无整屏闪烁；1s 刷新只刷时间区 |
| R10 | 长稳 | 连续运行 72h 不重启、不内存泄漏（heap 稳定） |
| R11 | 零配置可用 | 出厂只有固件时能进 AP 完成配网并开始显示 |
| R12 | 断电恢复 | 断电重上电 5s 内出时间（NTP 成功后），无需人工干预 |

## 2. 技术基线（已决策，不再讨论）

| 项 | 选择 | 理由 |
|---|---|---|
| 开发环境 | **PlatformIO + Arduino 框架**（同时能用 Arduino IDE 打开） | 多文件工程友好、库版本锁定、能跑 PC 单元测试 |
| 显示库 | **U8g2**，`SSD1306 128x64` 构造，**软件 I2C**（SCL=14, SDA=15） | ESP32-CAM 没有硬件 I2C 引脚；U8g2 的 SW I2C 支持自定义引脚且稳定 |
| 刷新 | 全屏缓冲 + `updateDisplayArea(0,0,16,2)` 局部刷新 | 1s 只刷时间区，避免闪烁 |
| 时间 | ESP32 SNTP：`configTime` + `sntp_set_sync_interval(12h)` + POSIX TZ `CST-8` | 免库、够用、可精确 12h |
| 天气 | **Open-Meteo**，苏州 `31.2989, 120.5853` | 免注册免 Key；返回 H/L、降雨概率、风、码 |
| HTTPS | v1 用 `setInsecure()`，v2 再上内置根证书 | 先把数据跑通；根证书需随固件更新 |
| JSON | **ArduinoJson 7** + `DeserializationOption::Filter` | 只解析需要的字段，省内存 |
| 存储 | `Preferences`（NVS）存 SSID/密码 | 掉电保存，无需文件系统 |
| 配网 | 自己写 AP + `WebServer`（中文页面） | 页面小、可控、好加 OTA 按钮 |
| OTA | `ArduinoOTA` + Web `/update`（`Update.h`） | 双通道，失效时可互救 |
| 中文字模 | 自制 **12×12 点阵子集（20 字）**，备选 `u8g2_font_wqy12_t_*` | 20 字 ≈ 360B，比整库省几百 KB |
| 图标 | 自绘 **22×22 单色位图 ×12**（PROGMEM） | U8g2 自带天气图标只有 6 个，不够用 |
| 农历 | 本地查表（1900–2100） | 不联网、不依赖第三方库 |
| 分区表 | **`min_spiffs`（1.9MB APP ×2）** | 双 app 才能 OTA；开 WiFi 后固件 1.2MB，1.2MB 分区的旧方案已不够 |

## 4. 核心数据结构

```c
struct WeatherNow {
  bool     valid;        // 是否取到过数据
  int8_t   temp;         // 当前温度（取整，无 °）
  uint8_t  wmo;          // WMO 天气码 -> 选图标
  int8_t   hi, lo;       // 今日最高/最低
  uint8_t  rain_pct;     // 今日降雨概率 0..100
  uint8_t  wind_deg;     // 0..360
  float    wind_ms;      // m/s
  bool     wind_ok;
  uint32_t last_ok_ms;   // 最后一次成功（用于右下角时间）
};

struct AppState {
  char      ssid[33], pass[65];
  bool      wifi_ok;
  bool      time_ok;
  int       tz_offset_h;   // 默认 8
  WeatherNow wx;
  uint32_t  last_ntp_ms, last_wx_ms, last_wifi_check_ms;
};
```

> 全部用固定大小 POD，不用 `String`，避免碎片。

## 5. 启动流程与调度

```
setup():
  1. display.init()            # 先点亮，立即给"正在启动"反馈
  2. settings.load()           # 读 NVS
  3. 有凭证 → STA 连接（15s 超时）；无凭证/失败 → AP 模式开网页
  4. SNTP 校时（等 time_ok，最多 10s；失败继续，但天气请求会跳过）
  5. 首次拉天气（HTTPS）
  6. 进入 loop()

loop()（非阻塞，millis 调度）:
  每 1s     : 刷新时间区
  每 10s    : 检查 WiFi 状态
  每 30min  : 拉天气（失败退避 1→5→30min）
  每 12h    : 校时
  一直      : 处理 WebServer / ArduinoOTA
```

## 6. 关键实现要点（提前踩坑）

### 6.1 U8g2 在自定义引脚上
- 用 **SW I2C** 构造：`U8G2_SSD1306_128X64_NONAME_F_SW_I2C u8g2(U8G2_R0, /*clock=*/14, /*data=*/15, U8X8_PIN_NONE);`
- 硬件 I2C 想用 14/15 需要在 `Wire.begin(15,14)` 之后绕过 U8g2 内部的 `Wire.begin()`，各 core 版本行为不一致 —— **不要赌，SW I2C 足够快**（整帧 ~30ms）。
- 地址先用 `0x3C`，扫描不到自动试 `0x3D`。

### 6.2 HTTPS 必须先校时
TLS 校验证书需要正确时间。**顺序必须是 WiFi → SNTP → HTTPS**；否则 v1 的 `setInsecure()` 虽能绕过，但以后换根证书会踩这个坑。

### 6.3 JSON 只解析需要的字段
用 filter 只保留 `current.temperature_2m / weather_code / wind_speed_10m / wind_direction_10m` 和 `daily` 三个数组，响应 ~2KB 时内存占用 < 6KB。

### 6.4 中文点阵怎么来
- 用 FreeType/Pillow 把"周一二三四五六日正八九十冬腊闰月初廿卅"渲染成 12×12 二值位图 → C 数组（脚本放 `tools/`，一次性生成）。
- 若嫌麻烦：先用 `u8g2_font_wqy12_t_gb2312` 顶上，确认 1.2MB 分区放得下再决定是否换子集。

### 6.5 农历
- 表驱动：`uint32_t lunarInfo[201]` + 春节基准 + 逐月累减。
- 必须过的样例：2026-11-02=九月廿四、2026-02-17=正月初一、有闰月的年份（如 2025 闰六月）、2100 边界。

### 6.6 断网/重启降级
- 天气失败不动 `wx.valid`，只更新退避计时；UI 永远画 `wx` 里最后一份。
- 时间未同步前显示 `--:--:--`。
- 右下角时间 = `wx.last_ok_ms` 对应的本地时刻，不是现在。

### 6.7 OTA
- 分区必须是双 app；上传前校验文件大小 < 剩余空间；失败回滚靠原有 app0。
- Web 上传与 ArduinoOTA 共用 `Update.h`。

### 6.8 供电
- 5V/2A + 100µF；HTTPS 握手瞬间电流最大，供电不足会 brownout → 表现为"随机重启"。

## 10. 风险登记表

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| Open-Meteo 在国内偶尔慢/不通 | 中 | 天气不更新 | 超时 8s + 退避；预留和风适配层（改一个文件） |
| ESP32-CAM 供电不稳（brownout） | 中 | 随机重启 | 5V/2A + 100µF；先用示波器看 5V 纹波 |
| 屏其实是单色 / 黄区行数不是 16 | 中 | 配色与设计不符 | 先做"全屏点亮"测试确认；把 `YELLOW_ROWS` 做成常量 |
| SW I2C 速度不够导致闪烁 | 低 | 观感差 | 先 SW I2C；必要时改 HW I2C + 局部刷新 |
| 中文字模工具链折腾 | 低 | 耽误半天 | 备选 `wqy12` 整库先顶上 |
| 农历表算错 | 低 | 显示错日期 | PC 单元测试 + 多源对照 |
| Flash 超 1.2MB 分区 | 低 | 无法 OTA | 字模子集 + 图标 PROGMEM；超了再加 `-Os` |

## 11. 需要你这边准备/确认

1. **WiFi**：2.4GHz 网络的 SSID / 密码（ESP32 不支持 5GHz）。
2. **屏幕确认**：全屏点亮时顶部 16 行是否是黄的（决定"黄色只给时间"是否成立）。
3. **硬件**：FTDI 或 ESP32-CAM-MB、5V/2A 电源、4 根杜邦线、100µF 电容（可选）。
4. **外壳**：有没有现成的，没有就按"裸板 + 亚克力/3D 打印"先放着。
