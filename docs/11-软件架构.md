# 11 · 软件架构

固件版本 **1.0.0-esp32cam** · 作者 **shane**

---

## 1. 总体结构

单任务超级循环（`setup()` + `loop()`），没有 RTOS 任务、没有阻塞式长操作（唯一例外是开机时的 WiFi 连接等待和天气 HTTPS 请求）。

```
                    ┌──────────────────────────┐
                    │        main.cpp          │
                    │  setup(): 初始化各模块    │
                    │  loop():  调度 + 渲染     │
                    └────────────┬─────────────┘
                                 │
        ┌───────────┬────────────┼────────────┬───────────┬────────────┐
        │           │            │            │           │            │
   net_time     net_weather   net_config   web_portal  ui_clock    ui_wx_icon
   (SNTP)      (Open-Meteo)   (NVS+AP)     (HTTP API)  (v6 排版)   (12 个图标)
        │           │            │            │           │            │
        └───────────┴────────────┴────────────┴─────┬─────┴────────────┘
                                                     │
                                            display.cpp (U8g2 软 I2C)
                                                     │
                                              SSD1315 128×64
        ┌────────────────────────────────────────────┐
        │  lunar.cpp（农历查表）  ← 被 ui_clock 调用  │
        └────────────────────────────────────────────┘
```

---

## 2. 模块职责

| 文件 | 职责 | 关键点 |
|---|---|---|
| `main.cpp` | 启动流程、主循环调度、OTA 回调、LED 状态、软看门狗、运行统计 | 所有模块的"粘合剂" |
| `display.cpp` | U8g2 初始化（软件 I2C）、I2C 地址探测（0x3C→0x3D→全扫）、自检 4 屏、OTA 进度屏、配网提示屏 | 引脚 SDA=15 / SCL=14 |
| `ui_clock.cpp` | v6 排版：时间 / 日期+星期+农历 / 虚线 / 天气 / 状态行 | 每秒只清 0–13 行 |
| `ui_wx_icon.cpp` | 12 个天气图标，全部用图元现画（圆、线、框） | 不用位图，避免 XBM 步长问题 |
| `net_time.cpp` | SNTP（阿里云/腾讯/国际池）、`CST-8`、每 12h 重校 | 时区在 `configTime()` 之后覆盖 |
| `net_weather.cpp` | Open-Meteo HTTPS、WMO→图标映射、风向/风级换算、失败退避 | 不校验证书（v1） |
| `net_config.cpp` | WiFi 凭证 NVS 读写、热点配网（AP + DNSServer + 表单） | 凭证优先级 NVS > config.h |
| `web_portal.cpp` | HTTP API：`/`、`/status`、`/update`、`/reboot`、`/debug/*` | 浏览器 OTA 用 `Update.h` |
| `lunar.cpp` | 1900–2100 农历查表 + 中文格式化 | 已与参考库逐日比对 |

## 3. 启动流程

```
上电
 │
 ├─ Serial 初始化 + 版本横幅（含作者）
 ├─ 读 NVS 统计：boots++
 ├─ displayBegin()  ──失败→ 仅打印错误，继续跑（灯闪 + OTA 仍可用）
 │     └─ I2C 扫描 0x3C → 0x3D → 0x00..0x7F
 ├─ displaySplash()   自检 4 屏（全屏亮 / 棋盘 / 边框文字 / 信息屏）
 ├─ LED 闪灯码：1=屏就绪  2=自检完成
 ├─ 读 WiFi 凭证：NVS → config.h
 │    ├─ 有 ──→ wifiStart()（15s 超时）
 │    └─ 无 ──→ 直接进配网
 ├─ LED 闪灯码：3=WiFi 阶段结束
 ├─ 若没连上 → cfgPortalBegin() + displayPortalScreen()，主循环只跑配网页
 ├─ timeBegin()      SNTP 启动
 ├─ weatherBegin()   首次 5 秒后拉
 ├─ webBegin()       HTTP 服务
 └─ otaSetup()       ArduinoOTA（UDP 3232）
      └─ LED 闪灯码：4=OTA 就绪
```

> **灯闪灯码**：1 次=屏就绪、2 次=自检完、3 次=WiFi 阶段、4 次=OTA 就绪。没有串口时靠它判断卡在哪。

## 4. 主循环调度

```
loop()
 ├─ ArduinoOTA.handle()            （仅 WiFi 就绪时）
 ├─ 每 2s 复查 WiFi 状态；恢复时补启 OTA/Web + 补拉天气/时间
 ├─ OTA 进行中 → 只画进度条，return
 ├─ timeTick()     12h 到点重校
 ├─ weatherTick()  30min 刷新 / 失败退避 1→5→30min
 ├─ webTick()      处理 HTTP 请求（必须在预览判断之前）
 ├─ 图标放大预览中 → 直接 return（不刷正常界面）
 ├─ 运行统计：minHeap、软看门狗（堆过低 5min / WiFi 断 30min → 重启）
 ├─ 取时间
 │    ├─ 分钟变了 / WiFi 变化 / 天气刚更新 → uiDrawAll()  整帧重画
 │    └─ 秒变了 → uiDrawTime()  只清 0–13 行 + 重画时间
 └─ 每 10s 打一条心跳日志
```

**刷新策略**：整帧只在"分钟变化 / 状态变化"时重画；每秒只重画时间区，减少 I2C 流量与闪烁。

## 5. 数据流

```
Open-Meteo HTTPS
   │  JSON（约 900 B）
   ▼
ArduinoJson（不设 filter，完整解析）
   │
   ├─ current: temperature_2m / relative_humidity_2m / weather_code
   │           wind_speed_10m / wind_direction_10m
   ├─ daily  : temperature_2m_max / min / precipitation_probability_max
   └─ hourly : precipitation_probability[0]（当前小时）
   ▼
WeatherData g_weather（全局单例）
   ├─ temp10  = 温度×10（避免浮点）
   ├─ icon    = WMO→WxIcon 映射
   ├─ windDir = (deg+22)/45 % 8   ← deg 必须用 int，用 uint8_t 会把 353 截成 97
   └─ windLevel = 蒲福风级查表
   ▼
ui_clock.drawWeather() → ui_wx_icon（图元绘制） → U8g2 缓冲 → I2C → 屏
```

## 6. 关键设计决策（含踩坑记录）

| 决策 | 原因 |
|---|---|
| **软件 I2C（SDA=15 / SCL=14）** | ESP32-CAM 的可用 GPIO 只有 10 个，只有这一对能同时满足启动 strapping |
| **SSD1315 按 SSD1306 驱动** | 两者命令兼容；地址 0x3C→0x3D→全扫 |
| **黄区只有 0–15 行** | 双色面板物理限制：日期行墨迹一旦进 16 行以上就变黄 |
| **每秒只清 0–13 行** | 清到 15 行会把日期顶部削掉（`周` 字少一横） |
| **图标用图元不用位图** | XBM 在屏上被按错误步长解码，显示成"三条竖带" |
| **中文必须 `drawUTF8`** | `drawStr` 按字节查字形，UTF-8 中文会变乱码 |
| **分区 `min_spiffs`（1.9 MB ×2）** | 开 WiFi 后固件 1.37 MB，1.2 MB 分区的旧方案会爆 |
| **OTA 走 UDP 3232** | ArduinoOTA 是 UDP，用 TCP 探测会误判为"端口关闭" |
| **降雨概率取 hourly** | `daily.precipitation_probability_max` 是全天最大值，晴天也常是 100% |
| **风向角度用 `int`** | `uint8_t` 存 353 会截断成 97（正好是"东"），导致方向永远错 |
| **先画屏再联网** | 无 WiFi 时初始化 mDNS/UDP 会挂住，表现为"黑屏" |

## 7. 资源占用

| 项 | 数值 |
|---|---|
| Flash（APP） | **1,402,723 B / 1,966,080（71%）** |
| RAM（全局） | 57,392 B / 327,680（17%） |
| 运行时空闲堆 | 约 200 KB |
| 天气 JSON | 约 900 B |
| 农历表 | 201 × 4 B = 804 B |
| 刷新频率 | 时间 1 次/秒；整帧 1 次/分钟 |

> 剩余 700+ KB Flash 可用于后续功能（如 TLS 证书、更多字体）。

## 8. 错误处理与自愈

| 故障 | 表现 | 处理 |
|---|---|---|
| 屏幕没接 | 显示空白，其余功能正常 | 打印错误，继续跑（OTA 仍可用） |
| WiFi 连不上 | 状态行 `WiFi NO` | 15s 超时后开热点配网；运行中掉线则每 2s 重连 |
| NTP 没同步 | 时间 `--:--:--` | 一直重试，同步后自动恢复正常 |
| 天气请求失败 | 保留旧数据 | 退避重试 1→5→30 分钟 |
| 天气数据超 2h | 更新时间前加 `!` | 提示数据可能过期 |
| 堆持续 < 20 KB | — | 5 分钟后自动重启 |
| WiFi 断超 30 分钟 | — | 自动重启 |
| 意外重启 | `boots` 增加 | `/status` 里 `boots` 与 `minHeap` 可追溯 |

## 9. 构建体系

```
firmware/
├── src/            应用源码（.cpp）
├── include/        头文件 + config.h（WiFi、坐标、版本、作者）
├── tools/
│   ├── build.cmd   ← 推荐入口（cmd 包装器，绕开 PowerShell 执行策略）
│   └── build.ps1   实际构建脚本：复制源码 → arduino-cli 编译 → 可选烧录/导出
├── platformio.ini  PlatformIO 备用配置（本机网络不可用，仅留存）
└── arduino/        Arduino IDE 导出目录（-Export 生成，gitignore）
```

构建脚本做的事：

1. 把 `src/*.cpp`、`src/*.h`、`include/*.h` 复制到 `.build/esp32clock/`
2. 生成 UTF-8 **无 BOM** 的 `esp32clock.ino`（有 BOM 会报 `'﻿' does not name a type`）
3. `arduino-cli compile --fqbn esp32:esp32:esp32cam --board-options PartitionScheme=min_spiffs`
4. 可选：串口烧录 / OTA（自动识别 IP 或 `.local`）/ 打开串口 / 导出 IDE sketch

详见 [08-接线与刷机教程](08-接线与刷机教程.md)。
