# 02 · 参考项目调研（GitHub 横评）

> 调研日期：2026-11-01。星数为当天抓取，会变化。
> 目的：看清"别人都实现了什么"，判断哪些能直接借、哪些必须自己写。

---

## 1. 调研方法

1. 用 GitHub Search API 多轮检索：
   - `esp32 oled weather clock`、`esp32 clock ssd1306 oled`、`esp32 weather station oled`
   - `esp32-cam oled`（重点：找同款板子）
   - `农历 esp32`、`lunar calendar`（中文日期）
2. 对候选仓库逐个读 README（必要时读主程序），确认"硬件 + 实现了什么"。
3. 按用途分四组：**A 可直接抄的软件栈 / B 同类桌面时钟固件 / C 中文与大屏进阶 / D ESP32-CAM 接线参考**。

## 7. 差异化结论（对我们最有用的 6 条）

1. **没有同款项目** → 软件自己写，但**复用 SSD1306 生态**，成本不高。
2. **SSD1315 一律当 SSD1306 处理**：没有人专门为 SSD1315 写 Arduino 时钟；libdriver 那个是底层驱动参考，不是应用层。
3. **国内数据源必须换**：OWM 免费版没有"逐日最高/最低"，中文作者基本都换成了和风/高德；免注册场景用 Open-Meteo。
4. **两条技术路线**：
   - `OLEDDisplayUi`（ThingPulse）：几十行就能有"多页 + 页指示点 + 过渡动画 + 进度条"，**但中文字形很弱**（只有内置 Arial 字体，中文得自己画位图）。
   - `U8g2`：中文点阵/图标/任意字体都行，**但页面管理要自己写**（约 100~200 行）。
   - 取舍见 [03 §1](03-功能候选与技术选型.md)。
5. **128×64 的信息密度上限很低**：一屏最多 1 个大时间 + 1 个图标 + 2~3 行小字。所有成熟项目都靠**多页轮播**，没有一个是"一屏塞满"。这也决定了 P0 里"多页"不是花活，是必需。
6. **OLED 的"亮度"= 对比度寄存器**（0x81 命令）。调低确实变暗，但不会像 LCD 背光那样省电；真正省电/护眼是**夜间定时熄屏**。
