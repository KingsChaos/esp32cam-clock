# 08 · 接线与刷机教程（M0）

> 目标：把 `firmware/` 里的 M0 固件跑到 ESP32-CAM 上，看到自检图 + 信息屏。
> 预计 30 分钟（含第一次装环境）。

---

## 1. 你需要什么

| 物料 | 说明 |
|---|---|
| ESP32-CAM（AI-Thinker） | 4MB Flash，带 OV2640（可保留，固件不初始化它） |
| SSD1315 OLED | 128×64，四针 I2C（七针模块要先配成 I2C 模式） |
| FTDI 编程器 | 或 ESP32-CAM-MB 底板（自带 USB） |
| 杜邦线 | 母对母 4 根 + 烧录用 5 根 |
| 电源 | **5V / 2A**（手机充电头即可） |
| 电解电容 | 100µF（可选，强烈建议） |
| 电脑 | Windows，装有 Python/arduino-cli（见 §4） |

## 2. 接线

![接线图](<images/08-接线图.png>)

### 2.1 OLED ↔ ESP32-CAM

| OLED | ESP32-CAM | 颜色（图示） | 说明 |
|---|---|---|---|
| `VCC` | **`3V3`** | 绿 | 不要接 5V（模块虽支持，但走板载 3.3V 更稳） |
| `GND` | `GND` | 黑 | 任一 GND |
| `SCL` | **`GPIO14`（D14）** | 蓝 | 有些模块丝印是 `SCK` / `CLK` |
| `SDA` | **`GPIO15`（D15）** | 蓝 | 有些模块丝印是 `SDA` / `DIN` |

> ⚠️ **四针模块的针脚顺序不统一**（有 `GND-VCC-SCL-SDA`，也有 `VCC-GND-...`），**接线前一定看丝印**，接反可能烧屏。
> ⚠️ 用了 14/15 之后 **SD 卡不可用**（这两脚本来是 SD 的 CLK/CMD）。

### 2.2 FTDI ↔ ESP32-CAM（烧录用）

| ESP32-CAM | FTDI | 说明 |
|---|---|---|
| `5V` | `VCC`（跳线选 **5V**） | 不要接 3.3V 供电 |
| `GND` | `GND` | 必须共地 |
| `U0R` | `TX` | **交叉** |
| `U0T` | `RX` | **交叉** |
| `IO0` | `GND` | **只在烧录时接**，烧完立刻拔掉 |

### 2.3 供电

- 从 **5V 脚**供电（不要用 3V3 脚供整板）；
- 5V 与 GND 之间并一个 **100µF** 电解，抑制 WiFi/TLS 瞬间掉压导致的 brownout；
- 杜邦线别太长，面包板接触不良会导致"随机重启"。

## 3. 刷机（三种方式，任选其一）

### 3.1 一行命令（推荐，Windows）

> ⚠️ 如果你的系统禁止运行 PowerShell 脚本（报"在此系统上禁止运行脚本"），
> **用 `build.cmd`**（内部已带 `-ExecutionPolicy Bypass`），在 **cmd** 里执行：

```bat
cd /d D:\CS\esp32display\firmware

:: 只编译
tools\build.cmd

:: 编译 + 烧录（COM5 换成你的端口）
tools\build.cmd -Upload COM5

:: 编译 + 烧录 + 串口
tools\build.cmd -Upload COM5 -Monitor COM5

:: 清缓存
tools\build.cmd -Clean

:: 导出给 Arduino IDE
tools\build.cmd -Export arduino\esp32clock
```

> 也可以用 `powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1 ...`，
> 或者一次性放开策略：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。

脚本内部做的事：

1. 把 `src/*.cpp` + `include/*.h` 拼成临时 sketch（目录 `esp32clock/` + `esp32clock.ino`，**无 BOM**）
2. 用 `esp32:esp32:esp32cam` + `PartitionScheme=min_spiffs`（**1.9MB APP ×2**，OTA 必需；开 WiFi 后固件已 1.2MB，1.2MB 分区会顶到头）编译
3. 产物：`firmware/.build/out/esp32clock.ino.bin`（约 491 KB）
4. `-Upload` 时调用 `arduino-cli upload`

### 3.2 arduino-cli 手动

```powershell
$cli = "$env:USERPROFILE\arduino-cli\arduino-cli.exe"

# 1) 装依赖（只第一次）
& $cli core install esp32:esp32 --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
& $cli lib install U8g2

# 2) 编译（脚本里已封装，手动等价于）
#    把 src/*.cpp + include/*.h 拷进 xxx/xxx.ino 的目录，然后：
& $cli compile --fqbn esp32:esp32:esp32cam --board-options PartitionScheme=default <sketch目录>

# 3) 烧录
& $cli upload -p COM3 --fqbn esp32:esp32:esp32cam --board-options PartitionScheme=default --input-dir <build目录>
```

### 3.3 PlatformIO（备用）

```ini
; firmware/platformio.ini 已配置好
board_build.partitions = default.csv   ; 双 app，OTA 必需
```

```bash
cd firmware
pio run
pio run -t upload
pio device monitor
```

> ⚠️ 本机实测 `pio run` 会卡在 `Downloading 0%`（PlatformIO 包 CDN 不通）。
> 换成**手机热点**或**代理**通常能过；否则用 §3.1。

### 3.4 Arduino IDE（图形界面，推荐给不习惯命令行的人）

**前提**：核心和库已装在 Arduino IDE 也会读的公共目录里（`%LOCALAPPDATA%\\Arduino15` + `Documents\\Arduino\\libraries`），所以 IDE 里应该已经能看到 `esp32` 板和 `U8g2` 库。

**步骤**

1. 先导出可打开的 sketch（只需一次，改了源码要重新导）：

```powershell
powershell -File D:\CS\esp32display\firmware\tools\build.ps1 -Export arduino\esp32clock
```

生成 `firmware\arduino\esp32clock\`（`esp32clock.ino` + `main.cpp` + `display.cpp` + 头文件）。

2. 用 Arduino IDE 2 打开：

```
D:\CS\esp32display\firmware\arduino\esp32clock\esp32clock.ino
```

3. 工具菜单设置：

| 菜单 | 选择 |
|---|---|
| 开发板 | **AI Thinker ESP32-CAM** |
| Partition Scheme | **Minimal SPIFFS (1.9MB APP with OTA/128KB SPIFFS)** ← 带 OTA，且放得下 WiFi+TLS |
| 端口 | 你的 CH340 端口（用 `arduino-cli board list` 确认当前是哪个，本机曾从 COM4 漂到 COM5） |
| Upload Speed | 115200（不稳就降到 460800→115200 试） |

4. 点 **上传**（→ 按钮）。ESP32-CAM-MB 底板会自动进下载模式；裸板需要 `IO0` 接地再按 RST。

5. 上传完打开 **串口监视器**，波特率 **115200**。

> ⚠️ 如果 IDE 里看不到 `AI Thinker ESP32-CAM`：文件 → 首选项 → 附加开发板管理器网址加
> `https://espressif.github.io/arduino-esp32/package_esp32_index.json`，再到开发板管理器装 `esp32`。

> ⚠️ 生成目录 `firmware/arduino/` 是**导出产物**，已 gitignore；不要在里面改代码，改 `src/` 后重新导出。

## 5. 首次上电看什么（自检流程）

上电后屏幕依次出现 4 屏：

| # | 画面 | 时长 | 看什么 |
|---|---|---|---|
| 1 | **全屏点亮** | 0.8s | **顶部约 16 行是不是黄色**（黄蓝双色屏）；有没有整行不亮 |
| 2 | **棋盘格** | 0.4s | 有没有坏点、缺行、花屏 |
| 3 | **边框 + y=15 分界线 + 文字** `TOP 16 ROWS / should be YELLOW` | 1.4s | 边框是否贴边、分界线位置是否准 |
| 4 | **信息屏**（每秒刷新） | 常驻 | 见下 |

信息屏内容：

```
ESP32-CAM CLOCK              M0
           00:00:12
I2C 0x3C  WIFI OK
192.168.1.23
```

- 第 1 行右端 `M0` = 当前里程碑
- 第 2 行 = 开机秒表（M0 还没接 NTP，M1 换成真实时间）
- 第 3 行 = 探测到的 I2C 地址 + WiFi 状态（`WIFI OK` / `WIFI NO`）
- 第 4 行 = IP；没配 WiFi 时显示 `no wifi config`
- **板载红灯（GPIO33）每秒翻转一次**

串口（115200）会打印：

```
ESP32-CAM CLOCK  0.1.0-m0
chip   : ESP32-D0WD rev1, 2 cores @ 240 MHz
flash  : 4096 KB
heap   : xxxxx bytes
[oled] 初始化成功，地址 0x3C
[i2c] ...
[wifi] 连接 "xxx" ...
[wifi] 已连接 192.168.1.23  rssi=-55 dBm
[ota] 就绪：主机名 esp32-clock.local
[boot] 进入主循环
[hb] up=10s heap=xxxx wifi=1 ip=192.168.1.23
```

## 6. 配 WiFi 与 OTA（M0 已支持）

编辑 `firmware/include/config.h`：

```c
#define WIFI_SSID "你的2.4G WiFi"     // 只支持 2.4GHz
#define WIFI_PASS "密码"
#define OTA_HOSTNAME "esp32-clock"
#define OTA_PASSWORD ""               // 留空 = 不校验
```

重新编译烧录后：

- 设备出现在路由器上，主机名 `esp32-clock`
- OTA 升级：

```powershell
powershell -File D:\CS\esp32display\firmware\tools\build.ps1 -Upload esp32-clock.local
```

升级时屏幕上会显示进度条。

**一行命令（推荐）**：

```bat
cd /d D:\CS\esp32display\firmware
tools\build.cmd -Upload 192.168.124.24        :: 用设备 IP
tools\build.cmd -Upload esp32-clock.local     :: 用 mDNS 名字（能解析时）
```

> ArduinoOTA 走 **UDP 3232**（不是 TCP），脚本内部用 esp32 核心自带的 `espota.py`。
> 用 IP 最稳；`.local` 需要 mDNS 解析。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 串口打印 `[oled] 未找到屏幕` | 接线错 / 没供电 / 地址不对 | 检查 SDA=15、SCL=14、3V3、GND；串口会打印全量 I2C 扫描结果 |
| 屏全黑但扫到了 `0x3C` | 对比度/初始化异常，或七针模块没配成 I2C | 换 `0x3D` 试试；查模块跳线 |
| 花屏、雪花 | I2C 线太长/接触不良 | 换短线，降速到 100kHz（`config.h` 里 `OLED_I2C_HZ`） |
| 烧录卡在 `Connecting...` / 报 `No serial data received` | 板子没进下载模式（MB 底板有时不会自动进） | **手动进**：按住 IO0 → 点一下 RST → 松开 RST → 松开 IO0，然后再点上传 |
| COM 口每次都不一样（COM3/4/5） | 板子插拔后重新枚举，旧口变"幽灵设备" | 用 `设备管理器` 或 `arduino-cli board list` 看**当前**这一个；残留在"未知"状态的口忽略 |
| 运行中反复重启 | brownout（供电不足） | 5V/2A、并 100µF、换短线；串口会打印 `Brownout detector was triggered` |
| 板子发热/不亮灯 | 5V 与 3V3 接反 | 立刻断电检查 |
| `pio run` 卡 0% | PIO CDN 不通 | 用 `tools\build.ps1`（§3.1） |
| `'﻿' does not name a type` | `.ino` 带 BOM | 用脚本生成（无 BOM），别用记事本另存 |
| PowerShell 报语法错 | `.ps1` 没存成 UTF-8 **带 BOM** | 用 VSCode "UTF-8 with BOM" 重存 |
| 找不到 COM 口 | 驱动没装 | FTDI 装 VCP 驱动；MB 底板装 CH340 驱动 |
| 有多个 CH340（COM3/COM4/COM5…），不知道选哪个 | 插拔后重新枚举，旧的变残留/幽灵设备 | 用 `arduino-cli board list` 或设备管理器看**状态 OK 的那个**；本机曾从 COM4 漂到 COM5 |
| 烧录成功但**串口 0 字节** | 板子仍在下载模式（IO0 被按住）/ CH340 的 RX 没接到 ESP32 TX | 松开 IO0 按 RST；换一根 USB 线；用 IDE 的串口监视器再试 |

## 8. 注意

1. **不要用 3V3 脚给整板供电**，容易 brownout。
2. `GPIO12` 是 strapping 脚，别拿来接东西（本方案没用到）。
3. 接屏后 SD 卡不可用，属预期。
4. 摄像头可以留着，但**固件里不要调用 `esp_camera_init()`**（会抢引脚）。
5. 烧完务必拔掉 `IO0-GND`，否则每次上电都进下载模式。

## 9. 下一步

自检通过后，把这三件事告诉开发者：

1. 面板是否黄蓝双色（顶部 16 行是否发黄）
2. I2C 地址（`0x3C` / `0x3D`）
3. WiFi 是否连上、串口有没有异常日志

然后进入 **M1**：SNTP 真实时间 + v6 单屏排版 + 1 秒局部刷新。

## 9. 调试接口（联网后可用）

设备在线后可以直接用浏览器/curl 查状态，不需要串口：

| 接口 | 作用 |
|---|---|
| `http://<IP>/` | 状态页（固件、IP、信号、天气、HTTP 码） |
| `http://<IP>/status` | 同上但返回 JSON（含 `lunar` 农历、raw 原始值、调试字段） |
| `http://<IP>/debug/wx` | 立刻重新拉一次天气 |
| `http://<IP>/debug/icon?n=0..11` | 把第 n 个天气图标放大到 48×48 显示 **15 秒**，图标名显示在黄区头部 |

> 图标编号：0 晴 / 1 少云 / 2 多云 / 3 阴 / 4 雾 / 5 毛毛雨 / 6 雨 / 7 大雨 / 8 雪 / 9 阵雨 / 10 雷 / 11 冻雨
>
> ⚠️ 屏的**上 16 行是黄色区**，所以预览图标整体画在 16 行以下的蓝区，避免被切成两截。

## 10. 首次配网（不用改代码）

固件 0.5.0-m5 起，WiFi 凭证存在 **NVS** 里，优先级：**NVS > `config.h`**。

### 情况 A：设备没配过网

1. 上电后屏幕显示 `CONFIG MODE`
2. 手机搜 WiFi，连 **`ESP32-Clock`**（开放热点）
3. 浏览器打开 **`http://192.168.4.1`**（多数手机会自动弹）
4. 下拉选你的 WiFi（页面已扫描好），填密码 → **保存并重启**
5. 重启后自动连上，屏幕恢复正常时钟

### 情况 B：换了 WiFi / 密码改了

设备连不上会**自动开热点**，重复上面步骤即可，**不需要重新烧固件**。

### 情况 C：想清掉已保存的凭证

串口烧一个空凭证版本，或临时用 `/debug/portal` 进入配网模式重新保存。

> ⚠️ ESP32 只支持 **2.4GHz**，5GHz 会一直连不上并停在配网模式。

## 11. 浏览器 OTA（最省事的升级方式）

设备联网后，不用 IO0、不用命令行：

1. 浏览器打开 `http://<设备IP>/update`
2. 选 `firmware/.build/out/esp32clock.ino.bin`（约 1.37 MB）
3. 点「上传并重启」，等约 20 秒

> 上传成功后设备自动重启，`/status` 里 `boots` 会 +1，`fw` 变成新版本号。

### 三种升级方式对比

| 方式 | 命令 | 需要 IO0 | 需要同一网络 |
|---|---|---|---|
| 串口 | `tools\build.cmd -Upload COM5` | ✅ 需要接地 | ❌ |
| ArduinoOTA | `tools\build.cmd -Upload <IP>` | ❌ | ✅ |
| **浏览器 OTA** | 打开 `/update` 上传 | ❌ | ✅ 手机也行 |
