## 1. 技术选型

### 1.1 显示库：三条路

| 方案 | 中文支持 | 页面管理 | 上手成本 | 适合 |
|---|---|---|---|---|
| **U8g2** | ✅ 内置文泉驿等中文字体（可只取子集），图标/BDF/自定义字体都行 | 自己写（约 100~200 行 PageManager） | 中 | **中文优先、想要自由排版** |
| **ThingPulse `OLEDDisplayUi`** | ❌ 只有内置 Arial，中文得自己画 XBM 位图 | ✅ 自带 frames / overlays / 过渡动画 / 进度条 | 低 | 快速出效果、英文界面 |
| **Adafruit_GFX + SSD1306** | ❌ 需自绘 | 自己写 | 中 | 最基础、教程最多 |
| LVGL | ✅ 但需外挂中文字库 | ✅ | 高 | 彩色屏；**128×64 单色屏不值得** |

**建议**：
- 如果**界面用中文** → `U8g2`（`u8g2_font_wqy12_t_*` 系列，或自制 16×16 子集字体），自己写一个极简 PageManager。
- 如果想**先看到效果** → 先用 `OLEDDisplayUi` 出英文原型，再决定是否换 U8g2。
- 两条路都能用 SSD1315（当 SSD1306 初始化），差别只在"画字/画图"的 API。

> 库地址：[U8g2](https://github.com/olikraus/u8g2) ｜ [ThingPulse esp8266-oled-ssd1306](https://github.com/ThingPulse/esp8266-oled-ssd1306) ｜ [ArduinoJson](https://arduinojson.org/) ｜ [WiFiManager](https://github.com/tzapu/WiFiManager)

### 1.2 其它基础库

| 用途 | 建议 | 说明 |
|---|---|---|
| JSON | **ArduinoJson 7** | ESP32 有 4MB PSRAM，解析不吃紧；仍建议用 `filter` 只取需要的字段 |
| 时间 | ESP32 core 自带 SNTP（`configTime` + `getLocalTime`） | 时区用 POSIX 串 `CST-8`；多任务下用 `localtime_r` 而不是 `localtime` |
| 配网 | **WiFiManager**（省事）或自写 AP + WebServer（约 100 行，可控） | 自写的好处：能做中文页面、能显示"配网中"到屏上 |
| OTA | `ArduinoOTA`（core 自带） | 必须选双 app 分区（见 01 §8） |
| 农历/节气 | 自实现查表算法（1900–2100，约 200 行 C） | **不联网**，也不依赖第三方库；中文 Arduino 农历库质量参差 |
| HTTP(S) | `HTTPClient` + `WiFiClientSecure` | 证书问题见 §2.3 |
| 图标 | 用现成 40×40/24×24 单色位图（G6EJD 那套可改） | 单色屏图标就是 bit array |

## 2. 天气数据源

### 2.1 对比

| 数据源 | 费用/额度（2026-11） | 优点 | 缺点 |
|---|---|---|---|
| **Open-Meteo** | 完全免费、**无需注册/Key** | 逐日最高/最低、降水概率、日出日落、UV、历史与预报都全；坐标即用 | 需较稳的国际网络；**中文天气词要自己映射**（WMO code → 中文） |
| **和风天气 QWeather** | 2025-04-01 起改按量计费，**每月 5 万次免费**，需在控制台生成**专属 API Host** | 中文字段最全：实时/逐日/空气质量/预警/生活指数；国内节点快 | 要注册；超额计费；Host 与 Key 都要配 |
| **高德天气** | 约 30 万次/日免费 | 国内快、中文、文档好 | 无体感温度/气压，字段较少 |
| **心知天气** | 免费版不限次数 | 简单 | 字段少（无湿度/风） |

> 数据来源：[和风官方公告（2025-03-01，免费额度改为每月 5 万次）](https://blog.qweather.com/announce/free-subscription-service-update/)、[NingZiXi/weather 的三家字段对比表](https://github.com/NingZiXi/weather)、[Open-Meteo 官网](https://open-meteo.com/)。

### 2.2 建议

- **v1 用 Open-Meteo**：零注册、零 Key，先把"时钟 + 天气"跑通，不用等账号审核。
- **v2 需要中文完整信息时切和风**：把"取数层"抽成一个接口（`fetchWeather(struct*)`），换源只改一个文件。
- 两者都按"经纬度"取数，切换成本低。

### 2.3 HTTPS 的两个坑（很重要）

1. **校时顺序**：TLS 证书校验依赖系统时间。正确顺序是 `WiFi 连上 → SNTP 校时 → 再发 HTTPS`。顺序错了会报证书无效/过期。
2. **根证书**：`WiFiClientSecure` 需要内置根证书（每个约 1~2KB，Flash 放得下）。根证书会轮换（Let's Encrypt、GlobalSign 都换过根），所以：
   - 简单粗暴：`setInsecure()`（不校验），个人玩具可接受，但没有中间人防护；
   - 稳妥：内置根证书 + 留 OTA 以便以后更新固件。
   - **建议**：v1 用 `setInsecure()` 快速跑通，v2 换内置根证书。

## 4. 推荐组合

### 性价比 Top 5（信息增量最大、实现最稳）

1. **农历 + 二十四节气**（#14/#15）：中文桌面时钟的"灵魂"，纯本地算法，不依赖网络。
2. **日出日落 + 白天进度条**（#18）：一屏就把"现在几点、天什么时候黑"说清楚了，API 免费就有。
3. **AQI + UV**（#19/#20）：日常最常看的两项，和风/Open-Meteo 都能给。
4. **室内温湿度**（#22）：一个 DHT22/SHT30 几块钱，屏上立刻"有生活感"。
5. **番茄钟 / 纪念日倒计时**（#27/#28）：不增加数据源，纯本地，使用频率却很高。

### 好玩加分 Top 3

1. **消息推送**（#36）：一行 URL 就能让屏上弹出"该喝水了"/"外卖到了"，比天气更有"存在感"。
2. **表情 / 宠物**（#33）：桌面小屏最容易让人会心一笑的功能，参考 desk_bot 的眨眼/睡觉。
3. **天气动画**（#32）：下雨天屏上真的在下雨，128×64 正好够用。

## 5. 架构与数据流（供后续实现参考）

```
WiFi ─► SNTP 校时 ─► HTTPS 取天气/空气质量 ─► JSON 解析
                              │
                              ▼
        数据快照 struct（time / now / forecast[3] / aqi / lunar / status）
                              │
                              ▼
        PageManager（页面数组，每页 render(data)）
                              │
                              ▼
        U8g2 / OLEDDisplayUi 绘制 ─► I2C ─► SSD1315
```

- **刷新策略**：时间 1s（只重画时间区域）、天气 15~30min、AQI 1h、NTP 6h。
- **线程模型**：v1 用单线程 `loop()` + `millis()` 非阻塞定时器，简单可靠；要做动画/多任务的 v2 再上 FreeRTOS（网络任务 + UI 任务 + 队列）。
- **I2C 速度**：默认 100kHz 时整屏 1KB 要 ~100ms，肉眼可见"刷屏"；**把 I2C 提到 400kHz（~25ms）**，再配局部刷新就顺滑了。
- **内存**：所有数据放固定大小 struct，别用 `String` 拼接；每帧复用同一块 buffer。

## 6. 边界情况与失败处理

| 场景 | 处理 |
|---|---|
| 首次上电、无配置 | 进 AP 模式，屏上显示 `AP: ESP32-Clock` / `192.168.4.1` |
| 有配置但连不上 WiFi | 30s 超时 → 显示"离线"，时间继续用内部 RTC 走（重启后归零） |
| NTP 未成功 | 显示 `--:--`，**不要**显示 00:00 骗人 |
| HTTPS 在校时前发起 | 禁止：必须先 NTP 再请求 |
| API 超时 / 429 | 指数退避 1min → 5min → 30min，**保留旧数据** |
| JSON 解析失败 / 字段缺失 | 保留旧数据，不清屏，状态栏标记 |
| 未知天气 code | 兜底图标 + "未知" |
| 屏幕初始化失败 | 重试 3 次，失败则红灯慢闪（可诊断），不进入死循环 |
| 跨天 / 跨月 / 闰年 | 全部用 `time_t` 标准运算，禁止手写日期加减 |
| 农历边界 | 算法限 1900–2100，超出直接不显示农历 |
| 长时间运行 | 每周自动重启一次（可选）；或监控 heap，低于阈值重启 |
| 断电重启 | 无 RTC 电池，时间从零开始 → 开机显示"同步中"，NTP 成功后恢复 |
| 中国无夏令时 | 时区写死 `CST-8`；但保留可配置，方便以后带出国 |

## 7. 里程碑草案（每步都能看到东西）

| 阶段 | 内容 | 验收标准 |

## 8. 明确不做（v1）

- 不做摄像头、不做视频流、不做图像识别（硬件上已拔掉）。
- 不做语音交互（没有麦克风/喇叭）。
- 不上彩屏/LVGL（128×64 单色用不上，纯属自找麻烦）。
- 不做电池管理/深度休眠（桌面常供电；ESP32-CAM 也没有电池电路）。
- 不做 SD 卡（引脚被 I2C 占用）。
