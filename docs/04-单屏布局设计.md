| 区域 | 行（y） | 水平位置（x） | 字体 / 样式 | 颜色 | 内容示例 |
|---|---|---|---|---|---|

| 底部留白 | 63 | — | — | — | 1px |

**对齐规则**

- **时间整串居中**：8 个字符（`HH:MM:SS`）定宽，秒跳变时整体不动。
- **时间和日期之间不画线**，用 15–18 行的纯黑空行隔开（黄区边界正好在这里）。
- **日期行整串居中**：`11-02` + `周一 九月廿四`，中文比拉丁高 1px，视觉等高。
- **右栏头尾对齐**：两行的左端都在 **x=68**（v6 从 62 右移），右端都在 **x=125**；第一行 `H 30` + `L 20`，第二行 `60%` + `E2`。右侧值右对齐到 125，所以 `E2` 正好落在 `L 20` 的数字下方。
- **图标与温度垂直居中**（v6）：图标 33–54（中心 43.5），温度 37–49（中心 43），右栏两行 35–51（中心 43）—— 三者共用一个视觉中轴。

## 5. 时间字体（7 段已撤回）

v5 试过 7 段数码，实际效果偏"硬"，已撤回；v6 换回 16px 文字字体（示意图用 Consolas Bold 近似，真机用 U8g2 `logisoso16_tn` 或 `9x15B`）。下面保留 7 段的记录，以后想再试可以参考：

| 做法 | 说明 | 推荐度 |
|---|---|---|
| **自绘段码**（推荐） | 用 7 段矩形直接画到 U8g2 缓冲：数字 → 段编码表（`0=abcdef`…），每段 2×2~2×5px，约 30 行代码，尺寸随意调 | ★★★ |
| U8g2 现成字体 | `u8g2_font_freedoomr10_tn`（10px）/ `freedoomr25_tn`（25px）/ `7segments_26x42_mn` —— 高度不是 13px，得要 10 或 25，二选一 | ★★ |

**段码表（ASCII 版）**

```
0: abcdef   1: bc      2: abdeg   3: abcdg   4: bcfg
5: acdfg    6: acdefg  7: abc     8: abcdefg 9: abcdfg
```

冒号用两个 2×2 方点（上 1/3、下 2/3 处）。

## 6. 右栏的两种排法（可选）

现在按你的要求做了"头尾对齐"：

```
H 30        L 20      ← 左端 x=62，右端 x=125
60%           E2
```

因为两行内容宽度不一样（`H 30`/`L 20` 各 4 字符，`60%`/`E2` 是 3/2 字符），所以第二行中间会有一个较宽的空白。如果你觉得空：

| 备选 | 效果 |
|---|---|
| A. 只左对齐 | `H 30  L 20` / `60% E2`，两行都从 x=62 起，右边不齐 |
| B. 加标签 | 第二行写 `R 60%  E 2`（R=雨，E=风），两行都变成"字母+数字"，宽度自然齐 |
| C. 居中 | 第二行 `60% E2` 在整块里居中，视觉平衡但不是表格感 |

## 7. 农历

- 格式：`九月廿四`（正月…腊月；初一…三十；闰月前缀"闰"）。
- 算法：1900–2100 农历查表，纯本地，约 150–200 行 C。
- **2026-11-02 = 九月廿四**（已核对），示意图用的是真实值。
- 字表（20 字）：`周 一 二 三 四 五 六 日 正 八 九 十 冬 腊 闰 月 初 廿 卅` ≈ 360 字节。

## 8. 数据映射（苏州）

```
https://api.open-meteo.com/v1/forecast
  ?latitude=31.2989&longitude=120.5853
  &current=temperature_2m,weather_code,wind_speed_10m,wind_direction_10m
  &daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max
  &wind_speed_unit=ms&timezone=Asia%2FShanghai&forecast_days=1
```

| 显示 | 字段 | 处理 |
|---|---|---|
| `23` | `current.temperature_2m` | 四舍五入、**不显示 °** |
| 图标 | `current.weather_code` | 查表 → 12 种图标 |
| `60%` | `daily.precipitation_probability_max[0]` | 取整 |
| `H 30` | `daily.temperature_2m_max[0]` | 取整 |
| `L 20` | `daily.temperature_2m_min[0]` | 取整 |
| `E` / `2` | `wind_direction_10m` / `wind_speed_10m` | 角度→8 方位、m/s→蒲福风级 |

> 该 URL 2026-11-02 实测返回：`14.7°C` / `code 53` / 风 `3.15 m/s` `312°` / `H 20.0` `L 12.7` / 降雨概率 `100`。

## 9. 刷新与状态机（不变）

| 项目 | 时机 |
|---|---|
| 时间 | 每 1 秒，只重画 y 0–15 |
| NTP | 每 12 小时 |
| 天气 | 每 30 分钟 |
| WiFi 状态 | 事件即时 + 每 10s 复查 |

```
BOOT → WIFI_CONNECTING → TIME_SYNCED → WEATHER_OK
                                   ↘ WIFI_LOST / HTTPS_FAIL
                                      → 旧数据 + "WiFi NO" + 更新时间停住
```

## 10. 已确认的设计决定

| 决定 | 结论 |
|---|---|
| 右下角加"更新"二字 | 不加 |
| 天气刷新间隔 | 30 分钟 |
| 农历 | 只做月日 |
| 数据位置 | 天气行右侧，两行 |
| 天气词 | 不显示 |
| 时间字体 | **16px 文字字体**（7 段数码方案已否决） |
| 时间/日期分隔 | **空行**，不画虚线 |
| H/L 写法 | `H 30` / `L 20`（有空格、无 °） |
| 温度与图标 | 垂直居中对齐（v6） |
| 右栏左端 | x=68（v6 右移 6px） |
| 数值单位 | **一律不显示 °**（大温度也不带） |

## 已实现坐标（固件 1.0.0-esp32cam）

实际固件里的坐标（`firmware/include/layout.h` 为准）：

| 元素 | 坐标/参数 | 备注 |
|---|---|---|
| 时间 | 8x13B，基线 **y=12**，水平居中 | 墨迹占 0–12 行；**0–15 行是黄区** |
| 日期 | 6x12（拉丁）+ wqy12（中文+农历），基线 **y=27**，整体居中 | 形如 `11-02 周一 九月廿四`，总宽约 110px（x0≈9）；墨迹必须 ≥16 行 |
| 分隔虚线 | y=**29**，x=3–125 | 4px 实 / 3px 空 |
| 天气图标 | 40×40 框内图元绘制，左上角 **(2,30)**，边长 24 | 不用位图，避免 XBM 步长问题 |
| 当前温度 | 8x13B，x=**33**，基线 y=**47** | **保留一位小数**（`17.2`），与图标空 4 列；4 字符宽 32px，右栏从 82 开始 |
| 右栏数据 | 5x7，左端 x=**82**，基线 y=**39 / 49**，数值右对齐 **127** | `H 20` / `L 13`，`64%` / `N1`；**百分比是相对湿度**（降雨概率在 `/status` 的 `rain` / `rainToday`） |
| 状态行 | 5x7，基线 y=**63** | 左 `WiFi OK/NO`，右最后更新时间；超 2h 加 `!` |

### 两个硬约束（踩过坑）

1. **黄区只有 0–15 行**：日期行墨迹一旦进到 16 行以上，笔画会变黄。
2. **每秒只清 0–13 行**（`L_TIME_CLEAR_H`）：清到 15 行会把日期顶削掉。
### 天气图标绘制规则（`src/ui_wx_icon.cpp`）

图标框 24×24（左上角 (2,30)），全部用 U8g2 图元现画，不用位图。

| 图标 | 构成 |
|---|---|
| 晴 | 实心圆盘 r=5 + 上下左右 4 条射线（射线从 `r+3` 起，与圆盘留 2px 空隙） |
| 少云 / 多云 | 小太阳 + 云朵（3 个圆 + 底部矩形） |
| 阴 | 两朵云叠加 |
| 雾 | 3 条横线 |
| 毛毛雨 / 雨 / 大雨 | 云 + 1 / 2 / 3 根竖线 |
| 雪 | 云 + 3 个十字 |
| 阵雨 | 小太阳 + 云 + 2 根竖线 |
| 雷 | 只有一道闪电（不带云） |
| 冻雨 | 云 + 3 根短竖线 + 3 个圆点 |

> 设计原则：24px 很小，任何"碎点"都会看着像乱码，所以只用大块形状。
