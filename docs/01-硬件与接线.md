# 01 · 硬件与接线

> 本文只描述"怎么接、为什么这么接"，不含任何代码。
> 数据来源：RandomNerdTutorials ESP32-CAM 教程、LastMinuteEngineers ESP32-CAM 引脚参考、libdriver SSD1315 驱动文档（链接见文末）。

---

## 1. 板子：AI-Thinker ESP32-CAM

| 项目 | 参数 |
|---|---|
| 模组 | ESP32-S（双核 Xtensa LX6，最高 240MHz） |
| 内存 | 520KB SRAM + **4MB PSRAM**（外挂） |
| Flash | **4MB**（决定分区表，见 §8） |
| 无线 | 802.11 b/g/n + BT/BLE 4.2 |
| 摄像头 | OV2640，**插座式排线**（可整块拔掉，不用焊） |
| 存储 | microSD 卡槽（用 I2C 后不可用，见 §5） |
| USB | **没有**，必须 FTDI 或 ESP32-CAM-MB 底板 |
| 板载 | 红色状态灯（GPIO33，低电平点亮）、白光补光灯（GPIO4）、RST 键、IO0 键 |
| 引脚 | 全板 16 个焊盘，其中**真正能当 GPIO 用的只有 10 个**：`0,1,2,3,4,12,13,14,15,16` |

> 关键认知：ESP32-CAM 不是"引脚少的 ESP32"，而是**引脚被摄像头和 SD 卡吃掉了大半的 ESP32**。拔掉摄像头只能"解放"摄像头排线座上的焊盘（没有引到排针），排针上真正能动的就是我们接 OLED 的那两根。

---

## 2. 去掉摄像头之后

- OV2640 是插在排线座上的，**直接拔**即可；不需要动烙铁。
- 拔掉后，摄像头占用的 `5,18,19,21,22,23,25,26,27,32,34,35,36,39` 在电气上"空闲"了，但**只有焊盘、没有排针**，要用得飞线，不推荐。
- 不拔也能用——只要**代码里不调用 `esp_camera_init()`**，那些脚就不会被配置，不影响 OLED。拔掉纯粹是为了省电、少干扰、看起来更像"桌面时钟"。
- 唯一"白送"的好处：板子背面那颗**红灯（GPIO33）**和**补光灯（GPIO4）**还在，可以用来做"联网状态灯"。

---

## 3. 排针上 10 个 GPIO 的真实可用性

| 丝印 | GPIO | 硬件事实 | 建议 |
|---|---|---|---|
| `D0` | 0 | 启动时必须为高（内部 10K 上拉）、下载时必须为低；同时是摄像头 XCLK | ❌ 不要用，留给烧录 |
| `TX0` | 1 | UART0 TX，烧录与日志 | ⚠️ 能用，但会吞掉串口日志 |
| `D2` | 2 | **启动时必须为低**；SD 卡 D0 | ⚠️ 慎用 |
| `RX0` | 3 | UART0 RX | ⚠️ 能用，但会吞掉串口日志 |
| `D4` | 4 | **板载补光灯 LED**；SD 卡 D1 | ⚠️ 可当按键/状态灯（代价：开灯时闪一下） |
| `D12` | 12 | **启动时必须为低**（MTDI，影响 Flash 电压选择）；SD 卡 D2 | ❌ 不要用（I2C 上拉会把启动搞坏） |
| `D13` | 13 | SD 卡 D3 | ✅ 可用（不用 SD 卡时） |
| `D14` | 14 | SD 卡 CLK | ✅ **推荐：I2C SCL** |
| `D15` | 15 | **启动时必须为高**（MTDO），否则丢启动日志；SD 卡 CMD | ✅ **推荐：I2C SDA** |
| `RX2` | 16 | UART2 RX；与 PSRAM 相关的模组上可能被片选占用 | ❌ 不要用 |

### 为什么是 15/14 这一对

1. **14/15 是唯一"启动电平要求与 I2C 上拉兼容"的组合**：I2C 总线靠上拉电阻把线拉高，而 GPIO15 恰好要求启动时为高（上拉正好满足），GPIO14 没有启动约束。
2. 相比之下 **GPIO12 / GPIO2 要求启动时为低**，一挂上拉电阻就可能起不来或者日志乱码 —— 所以坚决不用。
3. 这两个脚同时是 SD 卡引脚，所以**接了 OLED 就不能再用 SD 卡**；本项目不需要 SD 卡。

> 社区里所有 "ESP32-CAM + OLED" 的工程都用这一对，例如 [ClaudeMarais/ESP32-CAM_With_SSD1306](https://github.com/ClaudeMarais/ESP32-CAM_With_SSD1306)、[EntaerDev/Esp32cam-oledSSD1306](https://github.com/EntaerDev/Esp32cam-oledSSD1306)（后者明确写了 `GPIO14=SCL, GPIO15=SDA`）。

**备查：摄像头占用（拔掉后空虚，但没排针）**

| 信号 | GPIO | 信号 | GPIO |
|---|---|---|---|
| PWDN | 32 | Y5 | 21 |
| XCLK | 0 | Y4 | 19 |
| SIOD | 26 | Y3 | 18 |
| SIOC | 27 | Y2 | 5 |
| Y9 | 35 | VSYNC | 25 |
| Y8 | 34 | HREF | 23 |
| Y7 | 39 | PCLK | 22 |
| Y6 | 36 | RESET | 未接 |

**备查：SD 卡占用**：CLK=14、CMD=15、D0=2、D1=4、D2=12、D3=13。

**备查：仅输入 / 特殊脚**：GPIO34/35/36/39 只能输入、没有内部上拉；GPIO33 是板载红灯（低电平亮），未引到排针。

## 4. 推荐接线

| OLED 引脚 | ESP32-CAM | 说明 |
|---|---|---|
| `GND` | `GND` | 任意一个 GND 焊盘 |
| `VCC` | `3V3` | 屏驱动电流约 10–20mA（OLED 无背光），从板载稳压输出取 |
| `SCL` | `GPIO14`（D14） | 部分模块丝印为 `SCK`/`CLK` |
| `SDA` | `GPIO15`（D15） | 部分模块丝印为 `SDA`/`DIN` |

- **四针模块的针脚顺序不统一**（有 GND-VCC-SCL-SDA，也有 VCC-GND-SCL-SDA），**接线前务必看模块丝印**，反接会烧屏。
- 模块板载一般已有 4.7K/10K 上拉，**不需要外加**；如果屏幕是"裸屏"或长线，才考虑补 4.7K 上拉到 3V3。
- I2C 地址：绝大多数 `0x3C`，少数 `0x3D`（模块背面有个电阻位）。地址不确定时，先上机扫描一次再说。
- 如果以后还想用 SD 卡：只能放弃 I2C 走 GPIO14/15 的方案（这两根被占用），基本等于换板子 —— 本项目不做 SD 卡。

## 5. SSD1315 屏幕要点

| 项目 | 说明 |
|---|---|
| 分辨率 | 128 × 64 单色（SSD1315：128 segment × 64 common） |
| 接口 | I2C（也支持 6800/8080 并口、SPI，取决于模块引出） |
| 与 SSD1306 关系 | **命令集兼容**，SSD1306 的库/初始化序列可直接用；U8g2、Adafruit_SSD1306、ThingPulse 均按 SSD1306 处理即可 |
| 对比度 | 支持 256 级对比度调节（可用作"亮度"） |
| 供电 | 模块一般 3.3–5V（带 LDO），我们统一走 3V3 |
| 四针 vs 七针 | 七针模块（GND/VCC/SCL/SDA/RES/DC/CS）需要按丝印把 BS0/BS1 或 0Ω 电阻配成 **I2C 四线模式**，否则不亮 |
| 常见坑 | 花屏/半屏/全黑：地址错、模式错、上电时序（先给屏上电、延时 100ms 再初始化；必要时把 SDA 拉低几百 ms 做软复位） |

> SSD1315 是 SSD1306 的"替代/升级"型号，市面 0.96"/1.3" 128×64 模块大量使用。它的完整驱动实现可参考 [libdriver/ssd1315](https://github.com/libdriver/ssd1315)（62★，MISRA 规范，含 I2C 初始化序列）。

## 6. 供电与稳定性（ESP32-CAM 的老毛病）

| 项 | 做法 |
|---|---|
| 供电 | **5V 脚输入**，电源至少 5V/2A；官方建议不要用 3.3V 脚供电（很多人踩坑） |
| 电容 | 5V-GND 之间并 **100µF 电解 + 0.1µF 瓷片**，抑制 WiFi 发射瞬间的压降（brownout reset） |
| 线材 | 杜邦线别太长太细；面包板接触不良会导致"随机重启" |
| 屏幕取电 | 从 `3V3` 焊盘取，不要从 5V 取（模块 LDO 发热） |
| 外壳 | 金属外壳会挡天线，尽量让板子天线端朝外；亚克力/3D 打印壳最稳 |

典型故障现象：串口打印 `Brownout detector was triggered` 或反复重启 → 99% 是电源/线材问题，不是代码问题。

## 7. 首次烧录（FTDI）

| ESP32-CAM | FTDI | 备注 |
|---|---|---|
| `5V` | `VCC`（跳线选 5V） | 千万别接 3.3V |
| `GND` | `GND` | 必须共地 |
| `U0R` | `TX` | 交叉接 |
| `U0T` | `RX` | 交叉接 |
| `IO0` | `GND` | **只在烧录时接**，烧完必须拔掉 |

步骤要点：
1. 接好线，`IO0` 拉低 → 按一下 RST（或重新上电）进入下载模式。
2. Arduino IDE：开发板选 **AI Thinker ESP32-CAM**，端口选 FTDI 的 COM 口，点上传。
3. 看到 `Connecting........` 卡住 → 再按一次 RST，或检查 IO0 是否真的接地。
4. 烧完 → 拔掉 `IO0-GND` → 按 RST 运行。
5. 如果用的是 ESP32-CAM-MB 底板，直接插 USB 即可（底板自带 CH340 和自动下载电路）。

## 8. 分区表与 OTA

ESP32-CAM 只有 **4MB Flash**，分区表直接决定"能不能 OTA"：

| 分区方案（Arduino IDE） | APP 空间 | 能否 OTA | 建议 |
|---|---|---|---|
| `Default 4MB with spiffs (1.2MB APP/1.5MB SPIFFS)` | 1.2MB × 2 个 app 分区 | ✅ 能 | **推荐**（app0/app1 双分区，OTA 必需） |
| `Huge APP (3MB No OTA/1MB SPIFFS)` | 3MB | ❌ 不能 | 不选 |
| `Minimal SPIFFS (1.9MB APP with OTA)` | 1.9MB × 2 | ✅ 能 | 也可以，但没有文件系统空间 |

> 结论：**选带 OTA 的双 app 分区**。ESP32-CAM 没有 USB，每次插 FTDI 都很痛苦，第一次烧完就用 `ArduinoOTA` 无线更新，开发效率天差地别。
> 注意：中文字库如果太大（>1MB），1.2MB 的 app 分区会吃紧 —— 这也是 §9 建议做**字库子集**的原因之一。

## 9. 128×64 的显示预算（排 UI 前先算清楚）

| 项目 | 数值 |
|---|---|
| 整屏像素 | 128 × 64 = 8192 点 |
| 帧缓存 | **1024 字节**（1 bit/像素） |
| 5×7 ASCII（6px 步进） | 21 字符/行 × 8 行 |
| 8×13 ASCII | 16 字符/行 × 4~5 行 |
| 12px 中文点阵 | 10 字/行 × 4~5 行 |
| 16px 中文点阵 | 8 字/行 × 4 行 |
| 24px 高数字 | 约 5 位（`HH:MM` 刚好占满） |
| 32px 高数字 | 约 4 位（只够 `HHMM`） |
| 24×24 天气图标 | 一行可放 5 个 |
| 40×40 天气图标（G6EJD 方案） | 一行只能放 3 个 |

**字库体积**：GB2312 全集（6763 字）的中文点阵字库动辄上百 KB ~ 数百 KB，会挤爆 1.2MB 的 app 分区内空间预算，也让编译变慢。
→ 建议**只取子集**：星期（一~日）、节气（24 个）、节日（十几个）、天气词（晴/多云/阴/雨/雪/雾/霾/雷…）、单位（℃/%/米每秒/级），总共 200~300 字，12px 点阵约 **10KB 级别**。

## 10. 常见坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 屏全黑 | 地址不对 / 七针模块没配成 I2C / 上电时序 | 扫描 0x3C 与 0x3D；查模块跳线；先上电延时再初始化 |
| 花屏、雪花点 | 初始化序列或分辨率参数不对 | 按 SSD1306 128×64 初始化；对比度设 0xCF 左右 |
| 烧录一直 `Connecting...` | IO0 没接地 / FTDI 无 5V / TX-RX 没交叉 | 重新接线，按 RST |
| 运行中随机重启 | brownout（供电不足） | 5V/2A + 100µF；换短线；别用 3.3V 供电 |
| 启动日志乱/起不来 | GPIO12 被拉高 | I2C 别用 12（本方案已避开） |
| 开机没日志 | GPIO15 被拉低 | 保证 15 有上拉（OLED 板载上拉即可） |
| SD 卡不识别 | 14/15 被 I2C 占用 | 本方案不支持 SD 卡，属预期 |
| 摄像头相关报错 | 代码里调用了 camera 初始化 | 本方案完全不碰摄像头 API |

## 11. 待确认（需要你上机/看实物）

1. ~~屏幕是否双色~~ → **已确认（2026-11-02 上机）：0–15 行为黄色，16–63 行为蓝色，标准黄蓝双色**。尺寸仍待量（0.96" / 1.3" 从照片看更像 0.96"）。
2. 是 **四针 I2C** 还是 **七针 SPI/I2C 双模式**（七针要改焊盘/跳线）。
3. I2C 地址是 `0x3C` 还是 `0x3D`。
4. 手头 FTDI 是 3.3V 还是 5V 版（接 ESP32-CAM 要用 5V 档给板子供电，信号电平 3.3V 兼容）。
5. 有没有外壳/洞洞板/按键/传感器。
